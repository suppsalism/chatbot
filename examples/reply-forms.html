Reply forms

Any reply can carry a form, rendered inside that message's bubble, with its own onSubmit. The bot below asks a qualifying question, then collects contact details only once you say you want a follow-up.

  • Type anything → a plain reply with suggestion chips.
  • Say "contact" (or tap the chip) → a lead form; submitting it locks it and answers in the conversation.
  • Say "plan" → a select + checkbox form.
  • Say "reject" → a form whose handler returns false, so it stays editable.
  • Say "multi" → three separate bubbles from one turn.

The chips take a different route from typed text: onSendSuggestion answers contact and plan without ever reaching onSendMessage. It still awaits — a chip whose answer depends on the user may well need an API call — which is why it is written async here. multi is left unhandled on purpose, so it falls through and onSendMessage answers it instead.

Submitted values go to the console. Nothing leaves the page — there is no network call.
